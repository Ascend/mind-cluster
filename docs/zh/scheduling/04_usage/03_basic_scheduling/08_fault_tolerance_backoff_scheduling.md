# 故障退避容忍的降级调度<a name="ZH-CN_TOPIC_0000002480000001"></a>

## 使用前必读<a name="ZH-CN_TOPIC_0000002480000002"></a>

任务运行过程中，集群中可能存在一些不影响芯片健康状态、但可能会导致任务反复失败的芯片，例如以下两类：

- 静默故障芯片：节点反复出现软件故障、但在检测时间窗内无硬件故障上报时，由ClusterD综合判定为静默故障（SilentFault）。静默故障仅追加故障列表，不改变芯片健康状态，因此不触发Job/Pod/进程级重调度。
- Pod错误芯片：任务运行中因各类故障（含硬件故障）导致Pod失败时，该Pod本次所使用过的芯片。

针对这类芯片，Volcano提供基于时长的退避容忍机制：任务可通过注解配置退避时长，在退避窗口内，调度器不再把这类芯片分配给该任务（降级调度，不优先调度到这些芯片），窗口结束后自动恢复使用，从而避免任务被反复调度到故障芯片上导致持续失败。

**前提条件<a name="section166381652174501"></a>**

使用故障退避容忍的降级调度特性，需要确保已经安装如下组件。若没有安装，可以参考[安装部署](../../03_installation_guide/02_installation/00_helm_installation.md)章节进行操作。

- Volcano（本特性只支持使用Volcano作为调度器，不支持使用其他调度器。）
- Ascend Device Plugin
- ClusterD（静默故障芯片的检测与上报依赖ClusterD；仅使用Pod错误芯片退避时可选。）

**使用约束<a name="section117804491812701"></a>**

- 本功能仅支持在26.3.0及以上版本中使用。
- Pod错误芯片退避为临时退避，不支持配置为永久禁止（-1）。

**支持的产品形态<a name="section169961844182901"></a>**

支持以下产品使用**故障退避容忍的降级调度**。

- <term>Atlas推理系列产品</term>
- <term>Atlas训练系列产品</term>
- <term>Atlas A2系列产品</term>
- <term>Atlas A3系列产品</term>
- <term>Ascend 950PR&950DT系列产品</term>

**原理<a name="section579011371711101"></a>**

故障退避容忍按芯片粒度（而非节点粒度）生效，且两类退避相互独立：

1. 静默故障芯片由ClusterD上报给volcano调度器。
2. 任务的Pod失败时，调度器记录该Pod使用的芯片为当前任务的Pod错误芯片。Pod错误退避按任务维度生效：只有出错的任务在退避窗口内避让这些芯片，其他任务不受影响。
3. 调度时，调度器根据任务配置的退避时长，判断静默故障芯片与Pod错误芯片是否仍处于退避窗口内，若是则在候选芯片集合中剔除这些芯片，实现降级调度；窗口结束后自动恢复。
4. 当任务配置静默故障退避时长为-1（永久禁止）时，若已运行任务所在节点转为静默故障且任务使用了该芯片，调度器会将对应任务驱逐并触发重调度。

### 配置退避容忍<a name="配置退避容忍"></a>

在[整卡调度](./03_full_npu_scheduling.md#准备任务yaml)的任务YAML基础上，在 `metadata.annotations` 中新增以下字段。

```yaml
...
metadata:
  annotations:
    huawei.com/silent.unhealthy-tolerance.after-time: "1800"   # 静默故障芯片退避容忍时长，单位为s（秒）
    huawei.com/pod.error-tolerance.after-time: "60"            # Pod错误芯片退避容忍时长，单位为s（秒）
...
```

**表 1**  退避容忍配置项取值列表

<a name="table039616264491601"></a>

|参数| 默认值 |取值范围|含义|
|--|-----|--|--|
|huawei.com/silent.unhealthy-tolerance.after-time| 0   |[-1, 1800]|静默故障芯片退避容忍时长，单位为s（秒）。<ul><li>0：立即允许，不降级。</li><li>-1：永久禁止，任务不调度到静默故障芯片，已运行任务使用到静默故障芯片时会被驱逐并重调度。</li><li>N（N>0）：任务排队N秒后才允许使用静默故障芯片，N超过1800时按1800处理。</li></ul>|
|huawei.com/pod.error-tolerance.after-time| 0   |[0, 300]|Pod错误芯片退避容忍时长，单位为s（秒）。<ul><li>0：立即允许，不降级。</li><li>N（N>0）：任务在Pod失败后N秒内避让导致本次失败的芯片，N超过300时按300处理。</li></ul><p>Pod错误退避为临时退避，不支持配置-1（永久禁止）。</p>|

>[!NOTE]
>
>- 发生Pod重调度时，按"单Pod调度→逻辑框内所有Pod重调度→逻辑超节点重调度→Job重调度"逐级升级：先单Pod调度；3个session内框亲和无冗余资源，则将整个逻辑框的所有Pod重调度；6个session内超节点内无冗余逻辑框，则将整个逻辑超节点重调度；12个session仍调度失败，则回退到Job重调度。参见[逻辑超节点亲和性调度](./01_affinity_scheduling/04_node_based_affinity.md#逻辑超节点亲和性调度)和[逻辑框亲和性调度](./01_affinity_scheduling/04_node_based_affinity.md#逻辑框亲和性调度)的故障重调度说明。
>- Pod错误芯片退避为临时退避，窗口过短，则窗口结束后任务仍可能调度到原故障节点；窗口过长时，框内及超节点内均无冗余资源时，回退到Job重调度（整体重新调度）。可能会影响进程级重调度场景恢复时长。

### 验证退避容忍<a name="验证退避容忍"></a>

1. 构造静默故障芯片。

   请参见[配置静默故障检测](../04_fault_detection_and_diagnosis/03_configuration/09_silent_faults.md)开启静默故障检测，并等待ClusterD判定出静默故障芯片。

2. 下发配置了退避容忍的任务。

   按本章节[配置退避容忍](#配置退避容忍)修改任务YAML后下发任务。

3. 查看调度结果。

   - 当任务配置静默故障退避时长为正数时，在退避窗口内任务不会被调度到静默故障芯片上；超过退避时长后，任务可正常调度到这些芯片。
   - 当任务配置Pod错误退避时长为正数时，任务Pod失败后再次调度时，在退避窗口内会避让导致本次失败的芯片。
