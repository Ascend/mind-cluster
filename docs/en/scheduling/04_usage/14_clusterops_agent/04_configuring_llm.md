# Configuring and Clearing an LLM<a name="ZH-CN_TOPIC_00000026faultdiagnosis07"></a>

The ClusterOps Agent can connect to an LLM service to intelligently summarize the diagnosis report generated by ascend-fd and output a concise root cause report (fault event, root cause node, and recommended action). LLM configuration is optional. If it is not configured or the configuration is cleared, diagnosis automatically falls back to a deterministic diagnosis report without affecting the main diagnosis flow.

## Adding an LLM Configuration<a name="sectionfaultdiagnosisllmcreate"></a>

Add an LLM configuration with the `kubectl clusterops --create-llm-config` command. Interactive input, command line parameters, and environment variables are supported.

**Interactive input (recommended)**:

```shell
kubectl clusterops --create-llm-config
LLM API Key: ********
LLM Base URL:
LLM Model:
secret/llm-secret created
llm-secret updated, effective immediately
```

**Command line parameters**:

```shell
kubectl clusterops --create-llm-config \
  --base-url https://open.bigmodel.cn/api/paas/v4 \
  --model glm-4-plus
```

**Environment variables**:

After configuring the `LLM_API_KEY`, `LLM_BASE_URL`, and `LLM_MODEL` environment variables, running the `kubectl clusterops --create-llm-config` command reads the environment variables directly instead of prompting for input.

Where:

- `api-key` is mandatory and is provided by the LLM service provider.
- `base-url` and `model` are mandatory and are specified by the LLM service provider. They can be provided through the `--base-url` and `--model` parameters or the `LLM_BASE_URL` and `LLM_MODEL` environment variables; otherwise the command prompts for input. If left empty, the command reports an error and exits.
- The configuration is stored in the k8s Secret `llm-secret`, in the default namespace `mindx-dl`. The namespace can be overridden through the environment variable `ASCEND_CLUSTEROPS_NS`.

## Clearing the LLM Configuration<a name="sectionfaultdiagnosisllmclear"></a>

Clear all LLM configurations (api-key, base-url, and model are deleted together) with the `kubectl clusterops --clear-llm-config` command:

```shell
kubectl clusterops --clear-llm-config
secret "llm-secret" deleted
LLM config cleared, effective immediately
```

> [!NOTE]
> `--create-llm-config` and `--clear-llm-config` are mutually exclusive and cannot be used at the same time.

## Real-Time Effect<a name="sectionfaultdiagnosisllmeffect"></a>

Agent Core monitors `llm-secret` in real time (the corresponding RBAC `agent-core-llm` is already built into `agent-core.yaml`). Therefore:

- After the LLM configuration is added or updated, it **takes effect immediately without restarting Agent Core**.
- After the LLM configuration is cleared, Agent Core automatically falls back to a deterministic diagnosis report and does not call the LLM.
- When an LLM call fails (incorrect configuration, unreachable network, invalid api-key, and so on), the diagnosis result is returned with an `llm_error` indicating the cause, and the system automatically falls back to a deterministic diagnosis report without affecting the returned diagnosis result.
