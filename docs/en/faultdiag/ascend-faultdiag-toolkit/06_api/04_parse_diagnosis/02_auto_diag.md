## Command Function

Starts automatic diagnosis, which is suitable for unified diagnosis after batch collection.

- The tool reads structured data from the cache directory, checks all [diagnostic items](../../07_references/02_diagnosis_items.md), identifies link faults, and locates the root cause.
- You must first complete data collection through `auto_collect` (which can be executed multiple times in batches), and then execute `auto_diag` to start unified diagnosis.
- It can also be used to regenerate the diagnosis report separately after `auto_collect_diag` fails (for example, when the report file is occupied).

## Command Format

| Command Format | Description |
|---------|------|
| `auto_diag` | Starts automatic diagnosis, suitable for unified diagnosis after batch collection |
| `auto_diag ?` | Views details |

## Parameter Description

No parameters. `?` is a built-in help identifier used to view the command usage.

## Prerequisites

Before running `auto_diag`, ensure that structured data exists in the cache directory (generated by `auto_collect` or `auto_collect_diag`).

## Output Description

- Success: `Diagnosis complete`
- Report generation failed: `Report generation failed. Please release the file lock and run 'auto_diag' again to regenerate the report.`

## Examples

Non-interactive mode (command and output):

```bash
ascend-fd-tk set_conn_config /home/user/conn.ini auto_collect auto_diag
# Other log output...
Diagnosis complete
```

Interactive mode (showing commands and echoes):

```bash
ascend-fd-tk
>>> auto_diag
Diagnosis complete
```
