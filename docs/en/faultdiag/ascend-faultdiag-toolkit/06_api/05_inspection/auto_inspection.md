# auto_inspection

## Function

Starts inspection diagnosis and performs batch rule checks on the intermediate data generated by `auto_collect`. It is applicable to customized customer inspection scenarios, performing health checks on parsed device data according to predefined rules.

The inspection feature is a beta feature and is not recommended for use in production environments.

## Command Format

| Command Format | Description |
|---------|------|
| `auto_inspection` | Starts inspection result diagnosis, suitable for unified diagnosis after batch collection |
| `auto_inspection <customer_type>` | Starts inspection using the specified customer type |
| `auto_inspection ?` | Views details |

## Parameter Description

| Name | Type | Mandatory | Description                               |
|------|-----|------|----------------------------------|
| `<customer_type>` | String | No    | Customer type enumerations. Currently only `default` is supported. If not specified, `default` is used. |

## Output Description

- Success: `Diagnosis completed`
- Unsupported customer type: `{args} is an unsupported customer type. Use 'auto_inspection ?' to view supported customer types`

## Examples

Non-interactive mode (command and output):

```bash
ascend-fd-tk set_conn_config /home/user/conn.ini auto_collect auto_inspection default
# Other log output...
Diagnosis completed
```

Interactive mode (command and output):

```bash
ascend-fd-tk
>>> auto_inspection default
Diagnosis completed
```
