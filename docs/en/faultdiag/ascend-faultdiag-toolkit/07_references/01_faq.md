## Installation and Startup

### "ModuleNotFoundError: No module named 'ascend_fd_tk'" Reported at Startup

Check in sequence:

1. Whether the Whl package has been installed or it is in the source code directory.
2. Whether the current Python environment is the same as the one used during installation (a virtual environment is recommended for multi-version Python scenarios).
3. Whether the path where the `ascend-fd-tk` command resides has been added to the system `PATH` for Whl package installation.

### "error: invalid command 'bdist_wheel'" Reported During Whl Package Installation

The `wheel` packaging tool is missing. Run `pip3 install wheel --upgrade` and then repackage.

## Collection and Diagnosis

### Frequent "Connection Timeout" Errors During SSH Collection

Check in sequence:

1. Whether the target device IP/port is reachable.
2. Whether the account and password/private key in `conn.ini` is correct.
3. Whether the public key of the node where the tool resides has been added to `~/.ssh/authorized_keys` on the target device.
4. Whether port 22 is allowed by the network ACL/firewall.

### `auto_diag` Reports "Failed to Generate Report"

This is usually because the last report generation time is occupied by a process such as Excel or WPS. Close the occupying process and run `auto_diag` again to regenerate the report.

### Can Diagnosis Be Performed when only One Log Directory Is Set for Offline Log Diagnosis?

Yes. The tool supports independent diagnosis of a single device type (host only, BMC only, or switch only). You only need to set at least one log directory and then run `auto_collect_diag`. The diagnosis scope covers only the configured device types.

## Report Interpretation

### What Do The Color Markers In The Diagnostic Report Mean?

In the diagnosis report Excel file, the tab color of each sheet is used to distinguish report types (link analysis, fault diagnosis, optical module information, etc.). The cell colors within each sheet indicate fault severity levels: light red indicates a fault/anomaly requiring priority handling, light yellow indicates a warning/requires attention and is recommended for investigation, and light green indicates normal/passed with no action needed. For details, see [Diagnostic/Inspection Report Description](../05_usage/06_fault_analysis_report.md).

### What Is Difference Between Inspection Report (CSV) and Diagnostic Report (XLSX)?

The inspection report is generated by the `auto_inspection` command, which performs batch health checks based on predefined rules. It is output in CSV format and only records abnormal items. The diagnosis report is generated by the `auto_diag` command, which performs in-depth detection and root cause analysis for faults that have already occurred. It is output in XLSX format and contains multiple sheets, including link analysis, fault diagnosis, and optical module information. The inputs and outputs of the two are independent of each other.

### Unable to Locate Reports After Report Generation

- On Linux, reports are output to the `~/.ascend-faultdiag-toolkit/report/` directory by default.
- On Windows, reports are output to the `.ascend-faultdiag-toolkit/report/` directory under the current working directory by default.
- The diagnostic report file naming format is `diag_report_{YYYYMMDD_HHMMSS}.xlsx`, and that of the inspection report is `inspection_errors.csv`.
