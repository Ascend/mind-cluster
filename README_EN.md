## ℹ️ Introduction

MindCluster (AI cluster system software) is a set of deep learning components that supports NPU (Ascend AI Processor) training and inference hardware, enabling the construction of full-process cluster operations and providing functions such as job scheduling within an NPU cluster, O&M monitoring, and fault recovery. This helps deep learning platform vendors reduce the software development workload related to underlying resource scheduling and quickly enable partners to develop deep learning platforms based on MindCluster. In addition, it provides fault diagnosis tools (also called Ascend FaultDiag), including a log diagnostic tool (abbreviated as ascend-fd) and a link diagnostic tool (abbreviated as ascend-fd-tk), which can provide diagnosis results for problems such as cluster job failures and link faults.

## 🚀 Getting Started

**Cluster Scheduling**

MindCluster provides two quick start paths:

- **10-minute quick start**: Deploy only Ascend Device Plugin and Ascend Docker Runtime, use the native Kubernetes scheduler to schedule common Pods, and quickly verify NPU resource scheduling capabilities.
- **Training job quick start**: Deploy the complete set of cluster scheduling components (NodeD, Ascend Device Plugin, Ascend Docker Runtime, Volcano, ClusterD, and Ascend Operator), and use a PyTorch training job as an example to experience the end-to-end training process.

For details, see [Quick Start](./docs/en/scheduling/02_quick_start/quick_start.md).

**Fault Diagnosis**

- The log diagnostic tool provides a simple example for you to quickly experience its capabilities. For details, see [Quick Start](./docs/en/faultdiag/ascend-faultdiag/03_quick_start/quick_start.md).
- The link diagnostic tool provides a simple example for you to quickly experience its capabilities. For details, see [Quick Start](./docs/en/faultdiag/ascend-faultdiag-toolkit/03_quick_start/quick_start.md).

## 📦 Installation Guide

**Cluster Scheduling**

Multiple installation methods are supported:

- **Install using Helm (recommended)**: Deploy the cluster scheduling components with one click using a Helm chart.
- **Manual installation**: Install each component step by step, which is suitable for custom configuration scenarios.
- **Install using tools**: Quickly complete installation and deployment using automation tools.

Before installation, read [Before You Start](./docs/en/scheduling/03_installation_guide/00_before_you_start.md) and [Environment Dependencies](./docs/en/scheduling/03_installation_guide/01_environment_dependencies.md). For details, see [Installation Guide](./docs/en/scheduling/03_installation_guide/menu_installation_guide.md).

**Fault Diagnosis**

- The log diagnostic tool supports installation from source code and installation from a Whl package. For details, see [Installation and Deployment](./docs/en/faultdiag/ascend-faultdiag/04_installation_guide/01_installation.md).
- The link diagnostic tool supports installation from source code and installation from a Whl package. For details, see [Installation and Deployment](./docs/en/faultdiag/ascend-faultdiag-toolkit/04_installation_guide/01_installation.md).

## 📘 Usage Guide

**Cluster Scheduling**

MindCluster provides guides for environment installation and deployment (supporting multiple installation methods such as Helm, manual, and tool-based installation), containerization, resource monitoring, virtualization instances (vNPU), scheduling features (full-NPU scheduling, affinity scheduling, and multi-level scheduling), resumable training, and tidal scheduling, as well as best practices for various inference frameworks such as MindIE CMotor, SGLang, vLLM, and Infer Operator. For details, see [Cluster Scheduling User Guide](./docs/en/scheduling/menu_scheduling_user_guide.md).

**Fault Diagnosis**

- The log diagnostic tool provides two core functions: log cleaning and fault diagnosis. When a training or inference task exits abnormally or suffers performance degradation, ascend-fd can automatically extract key information from cluster logs, analyze the root cause node and fault events, and help users quickly locate issues. For details, see [Ascend FaultDiag User Guide](./docs/en/faultdiag/ascend-faultdiag/menu_ascend_faultdiag_user_guide.md).
- The link diagnostic tool provides both interactive and non-interactive operation modes, with two data processing capabilities: automatic online data collection and offline log cleaning. It can complete cluster device information collection and automated inspection and diagnosis, and locate link faults in a cluster through information from servers, L1/L2 UnifiedBus switches, RoCE switches, and BMC. For details, see [Ascend FaultDiag Toolkit User Guide](./docs/en/faultdiag/ascend-faultdiag-toolkit/menu_ascend-faultdiag-toolkit.md).

## 🔀 Version Maintenance Policy

The maintenance phases of version branches are as follows:

| Status                | Duration    | Description                                                         |
| ------------------- | ------- | ------------------------------------------------------------ |
| Planned                | 1-3 months | Planned features                                                     |
| Development                | 3 months   | Develop new features and fix issues, releasing new versions periodically                         |
| Maintenance                | 6 months   | Regular branches are maintained for 6 months. Major bugs are fixed, no new features are merged, and patch versions are released depending on the impact of the bugs |
