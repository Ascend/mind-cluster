# 隔离设备查询

## 什么时候用

- 列出被隔离的设备：**唯一来源是 ClusterD 的手工隔离名单（manual-info）**，不在名单上的设备不算已隔离；设备故障源里的隔离等级不生成名单。
- 典型问法："集群里哪些卡被隔离了？""有没有静默故障的卡？""node-1 的隔离情况？"
- 只读查询。判断"卡是否真的坏"用 `faulty-device`；判断"还有多少空闲卡可用"用 `cluster-resource`。

## 调用工具与参数

工具名 `isolated_device`（下划线，与注册名一致）。参数只有 `node` 一个：

| 参数 | 类型 | 规则 |
|---|---|---|
| `node` | 字符串数组，可选 | 省略或 null = 不限定节点（全量读取 ClusterD 名单）；传数组 = 只看这些节点；传空数组 `[]` = 显式空范围（不读来源，直接返回空 `data.node`）。一律传数组（单个字符串也会被服务端归一为单元素数组，公网 CLI 单值形态由此兼容） |

```json
{}
```

```json
{"node": ["node-1"]}
```

## 返回字段与解读

**返回是工具层原始信封 JSON**，不经过任何摘要或改写：`request_id`、`tool`、`status`、`elapsed_ms`、`data`、`errors[]`。下面的字段路径就是 JSON 里的实际路径，直接用路径引用，不要把整段 JSON 贴给用户。返回超过长度上限时末尾会带一句「已截断」声明：被截断的部分没有输出，不代表为空或不存在，需要完整数据请缩小 `node` 范围或改用 kubectl 查询，并把这一点写进结论。

数据入口 `data.node{}`：按节点名索引的字典（`{}` 是节点名占位），节点与设备均按名称排序。每个节点只有一个列表 `data.node{}.devices[]`，每条含：

- `device_id`：隔离设备名，只来自 ClusterD 名单（Total），不从明细扩充成员；
- `fault_level`：隔离等级**原始值**（如 `ManuallySeparateNPU`、`SilentFault`），**可能是逗号拼接的多值字符串**——转述与归类都以完整原串为单位，不拆成单值、不截断；
- `fault_code`：故障码，同样可能逗号多值，缺失为 null；
- `last_separate_time`：最近隔离时间，缺失为 null。

解读要点：

- **返回没有汇总计数**：没有总数，也没有按等级的分类计数。要报"人工隔离 X 台 / 静默故障 Y 台"这类分类时，必须自己按 `fault_level` 的完整原串归类（多值串整体算一类，不拆解）并标注「**由明细统计得出**」；要报总数就数 `devices[]` 条数。
- 「`status=ok` 且**实际读取范围内**名单为空（`data.node` 为空对象、或某节点 `devices[]` 为空数组）」才是**确定空集**：读取范围内 ClusterD 名单上没有隔离设备。`partial` 下空名单只代表"没读到"，不能说"没有隔离"；**显式空范围（`node: []`）产生的空名单只能表述为"未查询任何节点"，不得读作集群没有隔离设备**。
- 名单与明细可能不一致：名单内设备缺明细时仍保留（`fault_level` 为 `unknown`，其余为 null）；只在明细里出现的设备不返回、不计数。
- 隔离记录与故障记录是两套口径：同一张卡可能既有故障记录又在隔离名单，跨技能引用时说清来自哪个工具。

## 无数据与异常提示

- 外层 `status` 是**查询质量**而非集群健康：`ok` 说明本次结果完整；`partial` 说明只查到一部分——先给已观察到的结果，再说缺口。**缺口分两层**：名单内设备缺明细时 `fault_level` 为 `unknown`、其余为 null（返回中可见）；点名了却未出现在 `data.node` 中的节点 = 未能读取或不存在（返回中不可见，凭 `request_id` 查服务端日志）；`error` 说明执行失败（`data` 为 null，按 `errors[].code` 说明原因，不要回答"没有隔离/一切正常"）。
- `errors[]` 只承载执行失败（`INVALID_ARGUMENT` / `TOOL_NOT_FOUND` / `INTERNAL_ERROR`），条目含 `code` 与 `message`，`retryable` 恒为 `false`，不要据此自动重试。
- 仅 `status=ok` 且本次**实际读取过节点**时空名单才可读作"确定没有隔离设备"（显式空范围产生的空名单除外，见上）。
- 只读技能：不执行解隔离、重启或其他修复；需要动作时引导用户走命令行或变更流程。

## 回答格式（三段式，缺一不可）

1. **总结**：1~3 句直接回答，先给结论（有几台被隔离、涉及哪些节点；没有就明确说"名单为空"）。
2. **依据**：逐条列出结论出处，写清工具名与字段路径（如 `isolated_device` → `data.node{}.devices[].fault_level`），分类计数要标注「由明细统计得出」，数值必须与返回一致。
3. **说明与建议**：先交代本次缺口与限制（`partial`、截断、`fault_level=unknown`、null 字段、点名了却没返回的节点），再给下一步建议（查故障用 `faulty_device`、查空闲卡用 `cluster_resource`、需要解隔离走变更流程）。

三段都要写，也不要把整段信封 JSON 贴给用户。

## 禁止事项

- 不编造返回里没有的字段、设备名、故障码或计数；空名单不等于集群健康。
- 不把技能名当工具名：本技能名是 `isolated-device`（连字符），要调用的工具名是 `isolated_device`（下划线，与注册名一致，不存在连字符变体）。
- 不跨技能臆测：设备故障查 `faulty_device`，隔离名单查 `isolated_device`，资源查 `cluster_resource`，任务状态查 `task_status`，任务日志诊断查 `diagnose`。

契约依据：`agent-core/tools/builtin.py`（工具注册）、`query_schemas.py`（入参与返回模型）。
